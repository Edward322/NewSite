# Этап 2. Бэктестер — итог

Числа о проверке на реальных данных взяты из
[`reports/stage2_validation.txt`](stage2_validation.txt)
(генерирует `python -m research.stage2_validation`). Тесты: `python -m pytest` — 89 тестов.

## Как устроен

- **События.** Время идёт свечами таймфрейма стратегии, внутри свечи — по минутам
  (минутные свечи по последней и по mark-цене).
- **Без заглядывания в будущее.** Стратегия получает свечу только после её
  закрытия; решение исполняется по открытию следующей минуты.
- **Порядок внутри свечи:** финансирование за уже открытую позицию → исполнение
  решения прошлой свечи → поминутная проверка стопа, тейка, ликвидации и порога
  просадки → закрытие свечи, проверки риска, новое решение.
- **Риск-модуль общий с будущим торговым движком** (`bot/risk/`): размер позиции
  от риска и стопа, плечо, ограничители. Стратегия только говорит «вход/выход/стоп».
- **Отложенные данные закрыты в коде:** исследование загружает период
  2025-01-01 — 2026-04-01; последние 6 месяцев открываются только явным
  подтверждением, каждое обращение пишется в журнал.

## Что учитывается

| Что | Как |
|---|---|
| Комиссии | taker 0,055 % на рыночные входы/выходы и стопы, maker 0,02 % на тейк-профит |
| Проскальзывание | 0,02 % на каждую рыночную сделку |
| Стоп в быстром рынке | исполнение хуже стопа на 25 % пути от стопа до экстремума минуты; при гэпе — от цены открытия |
| Финансирование | каждые 8 ч по mark-цене, только если позиция была открыта в момент выплаты |
| Округление | стоп — наружу до шага 0,01; объём — вниз до шага 0,01; плечо — вниз до шага 0,01 |
| Минимумы биржи | сделка меньше 5 USDT пропускается, риск ради неё не увеличивается |
| Ликвидация | изолированная маржа: срабатывает по mark-цене, теряется вся маржа позиции |
| Плечо | максимальное, при котором ликвидация вдвое дальше стопа; не выше лимита биржи для уровня риска (75 сейчас) |
| Ограничители | 5 % на сделку; −25 % за день UTC → пауза до конца дня; 4 убытка подряд → пауза 24 ч; −80 % от пика → полная остановка (проверяется и внутри свечи) |

## Доказательства отсутствия заглядывания в будущее (`tests/test_lookahead.py`)

1. Каждая сделка исполнена не раньше момента решения и ровно по цене открытия
   следующей минуты.
2. **Обрезка:** бэктест на данных до момента C даёт те же решения и сделки до C,
   что и на полных данных.
3. **Подмена будущего:** если после момента C заменить цены случайными, решения
   и сделки до C не меняются.
4. **Проверки ловят утечки:** стратегия, подглядывающая в следующую свечу, и
   стратегия со скрытой утечкой (нормировка по средней всей выборки) обе
   проваливают проверки. Подглядывающая на 20 днях случайных данных превращает
   10 USDT в 4 185 — так выглядит заглядывание в будущее.
5. Проверки 2–3 пройдены и на реальных данных HYPEUSDT.

Эти же проверки будут автоматически применяться к каждой стратегии этапа 3.

## Проверка на реальных данных (период разработки)

Тестовая стратегия — пересечение скользящих средних. Она нужна только для
проверки движка и **не является кандидатом**; её убыточность ничего не говорит
о стратегиях этапа 3.

| | 15m | 1h |
|---|---|---|
| Время прогона за 456 дней | 0,36 с | 0,14 с |
| Сделок | 90 | 131 |
| Независимый пересчёт сделок | расхождение ≤ 4,4·10⁻¹⁶ | ≤ 2,2·10⁻¹⁶ |
| Нарушения причинности (3 обрезки + 3 подмены) | нет | нет |
| Фактический убыток на стопе / плановый: среднее, 95-й перцентиль, худший | 1,024 / 1,044 / 1,890 | 1,011 / 1,056 / 1,136 |
| Плечо: мин / медиана / макс | 8,49 / 18,48 / 41,80 | 5,21 / 14,81 / 28,57 |
| Входов пропущено из-за минимума 5 USDT | 8 | 97 |

## Что это значит для этапа 3

1. **Минимальный ордер 5 USDT при депозите 10 USDT — серьёзное ограничение.**
   Риск 5 % от 10 USDT = 0,5 USDT, значит стоп не может быть дальше 10 % от
   входа; после просадки до 5 USDT — дальше 5 %. На 1h тестовая стратегия
   пропустила 97 входов по этой причине. Стратегии с широкими стопами при
   малом капитале просто не смогут торговать — это будет видно в отчёте.
2. **Реальный убыток на стопе в среднем на 1–2 % больше планового, в худшем
   случае (гэп) — в 1,9 раза.** Это следствие консервативной модели исполнения
   стопа; при проверке устойчивости проскальзывание будет удвоено.

## Известные упрощения

- Формула ликвидации — стандартная для изолированной маржи, с запасом на
  комиссию закрытия; в бою бот берёт фактическую цену ликвидации с биржи.
- Параметры инструмента (шаг цены 0,01, уровни риска) применены ко всей истории
  в текущем виде; для прошлого это немного хуже реальности.
- Доля «проскальзывания стопа» (25 %) — допущение: внутриминутных сделок в
  данных нет. На этапе 3 проверяется чувствительность (удвоенные издержки).
- Предполагается, что бот реагирует в течение минуты после закрытия свечи.

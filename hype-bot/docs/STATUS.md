## Задача пользователя (текущая)

Бот торгует сам, круглосуточно, на ПК пользователя (Windows без Docker). Порядок такой:
1. проверка на демо-счёте Bybit как на новых данных;
2. реальные деньги — только после явного «да» пользователя.

Исследование закончено: новые стратегии на истории не ищем, отложенные данные израсходованы.

## Правила работы

- Работать самостоятельно. Останавливаться только там, где нужно действие пользователя
  (ключи, запуск скрипта), и перед live.
- Все цифры — только из выполненного кода. Прибыль не обещать.
- Ограничители не ослаблять, стратегию ради красивого результата не менять.
- Правила записывать до прогона: `docs/RISK_PROTOCOL.md`, `docs/DEMO_PROTOCOL.md`,
  `docs/LIVE_PROTOCOL.md`.
- Ключи — только в `.env` на ПК пользователя. Никогда не в облаке и не в git.
- API Bybit из облачной среды закрыт (CloudFront 403). Поэтому движок проверяется на
  имитаторе `bot/exchange/sim.py`, а настоящую биржу проверяет пользователь:
  - `windows\selfcheck.bat` — самопроверка;
  - `windows\demo_report.bat` — отчёт по демо.

  Вывод пользователь присылает в чат.
- Коммиты по этапам; тесты должны проходить (`cd hype-bot && python -m pytest`, около 8 минут:
  тесты движка на имитаторе прогоняют недели торговли).

## Параметры пользователя

- Депозит 25 USDT, аккаунт bybit.com, статический IP.
- Комиссии: мейкер 0,02 %, тейкер 0,055 %.
- Риск 1–2 % на сделку: выбран **2 %** по правилу «пропуск из-за минимального ордера ≤ 20 %».
- Суммарный открытый риск ≤ 6 %, дневной лимит 6 %.
- Просадка 20 % → риск вдвое; 40 % → полная остановка. Пауза после серии убытков убрана.
- Таймфрейм не ниже 4h. Демо — минимум 1 неделя.
- Telegram и круглосуточная работа ПК: в задаче не уточнено. Сделано так: Telegram
  необязателен, ПК должен быть включён.

### Этап 1: что выбрано (`reports/STAGE1_RISK.md`)
- Пробой канала 4h с параметрами из центра плато: n = 38, k_stop = 2,5, k_trail = 4,
  обе стороны, без фильтров. Квартальный переподбор убран.
- Риск 2 %.
- Вариант B: сумма открытого риска ≤ 6 % и риск с учётом корреляции ≤ 4 %.
- Правило ликвидности: шаг цены ≤ 0,04 % цены, оборот ≥ 10 млн USDT в сутки, свечей без
  сделок ≤ 1 %. Отсекает MOVR и QNT почти всегда.
- Вся история (данные не чистые): 25 → 30,34 USDT, просадка 37,4 %, PF 1,08.
  Справочный капитал: средний R +0,07.
- **Главная оговорка:** при 25 USDT режим половинного риска (просадка ≥ 20 %) почти
  останавливает торговлю — 94 % сигналов меньше минимального ордера. Так прошло 70 %
  времени. Вопрос о депозите оставлен пользователю; ограничители не менялись.
- Конфиг: `config/bot.example.yaml`. Установщик копирует его в `config/bot.yaml`.

### Этап 2: устройство движка
- `bot/risk/planner.py` — планирование свечи. Один код для бэктеста и движка: ограничители,
  места, лимиты риска, объём.
- `bot/engine/engine.py`:
  - каждый ордер записывается в SQLite с orderLinkId «свеча+монета+цель» до отправки;
  - вход и стоп отправляются одним запросом;
  - сверка с биржей при старте и каждые 60 с;
  - блокировки входов: устаревший WebSocket, неполные данные, недоступный API,
    расхождение с биржей;
  - остановка при просадке 40 %; файл `STOP` — аварийная остановка;
  - на демо капитал бота ограничен 25 USDT (смещение от баланса счёта).
- Известное расхождение с бэктестом: финансирование в момент закрытия свечи биржа
  списывает до решения движка, а бэктест — после. Поэтому объём может отличаться на шаг.
  Без финансирования совпадение точное (тесты в `tests/test_engine_sim.py`).

### Этап 4: как проходит демо
- Критерии: `docs/DEMO_PROTOCOL.md` — движок, исполнение, совпадение с бэктестом,
  бутстрэп-интервал из `reports/stage1/baseline.json`.
- Отчёт: `python -m bot.report.demo` (`windows\demo_report.bat`) → `reports/DEMO_REPORT.md`.
- Сравнение: `python -m bot.report.compare`.

## Как продолжить в новой сессии

1. Прочитать этот файл, `README.md` (инструкция пользователя), `docs/DEMO_PROTOCOL.md`.
2. Запустить тесты: `cd hype-bot && pip install -r requirements-dev.txt && python -m pytest`.
3. Если пользователь прислал **вывод самопроверки** (`selfcheck_demo_*.txt`), проверить:
   - права ключа: нет вывода средств;
   - режим маржи: ISOLATED_MARGIN;
   - пробный ордер:
     - вход со стопом одним запросом;
     - повтор orderLinkId отклонён кодом 110072;
     - неверный стоп отклонён; движок распознаёт ошибку по словам «StopLoss» и «base_price»
       (`_move_stop`);
     - reduce-only без позиции — код 110017;
   - журнал финансирования доступен;
   - WebSocket подключён.

   Если какие-то коды или поля Bybit отличаются от ожидаемых, поправить `bot/exchange/client.py`
   и `bot/exchange/sim.py`, затем попросить пользователя запустить `windows\update.bat`.
4. Если пользователь прислал **`DEMO_REPORT.md`**:
   - разобрать критерии;
   - при расхождениях — по таблице сравнения и журналу (`logs/bot_demo.log`, таблица
     `events` в `data/state/bot_demo.sqlite`);
   - итог «РАНО» — демо продолжается.
5. **Live — только после явного «да» пользователя** (`docs/LIVE_PROTOCOL.md`):
   - поставить `live.enabled: true` в `config/bot.example.yaml` и дать инструкцию
     (README, раздел «Реальные деньги»);
   - пользователь в своём `config/bot.yaml` тоже ставит `true`: этот файл `update.bat`
     не перезаписывает.
6. Обновления кода у пользователя: `windows\update.bat`. Он скачивает архив ветки,
   указанной в `update.bat` (переменная BRANCH). Если ветка сменилась — поменять BRANCH.

  - `engine.py` — движок;
  - `state.py` — SQLite;
  - `data.py` — живые данные;
  - `stream.py` — WebSocket;

  - `reports.py` — «жив» и недельный отчёт;

  - `__main__.py` — команды run/kill/resume/status.

  - `client.py` — Bybit V5;
  - `sim.py` — имитатор с инъекцией сбоев.

  - `sizing.py`, `guards.py` (ступени просадки);
  - `portfolio.py` — сумма и корреляция, волатильность, ликвидность;
  - `planner.py`.
- `bot/report/` — отчёты:
  - `execution.py` — качество исполнения;
  - `shadow.py` — теневые варианты на живых данных;
  - `weekly.py`;
  - `compare.py`;
  - `demo.py`.
- `bot/selfcheck.py` — самопроверка на настоящей бирже.
- `bot/setup_env.py` — мастер ключей.
- `bot/runtime.py` — сборка стратегии и бэктеста из конфига.
- `bot/strategy/basket.py` — `Breakout`, `BreakoutShadow` (S1 — ADX ≥ 20, S2 — только лонг
  в бычьем режиме, S3 — оба фильтра).
- `windows/` — install, run_bot, stop_bot, resume, status, selfcheck, demo_report, update,
  uninstall, register_task.ps1.
- `research/stage1_risk.py` — прогон этапа 1 (данные корзины — релиз `data-v2`, только для
  исследований; боту они не нужны).

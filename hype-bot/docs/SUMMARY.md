# Итоги проекта «торговый бот Bybit» — для разбора в новом чате

Репозиторий `Edward322/NewSite`, ветка `claude/wonderful-ramanujan-6lakcx`, код в папке
`hype-bot/`. Состояние на 2026-10-02.

## 1. Исходная задача и ограничения пользователя

**Задача.** Агрессивный бот для бессрочных USDT-контрактов Bybit:
- сначала только HYPEUSDT, потом корзина монет;
- сначала депозит 10 USDT, сейчас **не больше 25 USDT**;
- цель — максимальная прибыль.

**Риск-модуль из исходного ТЗ:**
- стоп-лосс на бирже вместе со входом;
- изолированная маржа;
- дневной лимит убытка 25 %;
- остановка при просадке 80 % от пика;
- пауза на 24 ч после 4 убытков подряд;
- без мартингейла;
- аварийная остановка одной командой.

**Безопасность:**
- ключи API только в `.env`;
- ключ только с правом торговли, без вывода, с привязкой к IP.

**Приёмка на отложенных 6 месяцах** (все условия сразу):
- профит-фактор > 1,3;
- ≥ 100 сделок;
- просадка в пределах лимита;
- результат лучше buy & hold с поправкой на риск.

**Порядок работы:**
- план → данные → бэктестер → исследование → движок → демо → live;
- после каждого этапа — остановка и подтверждение;
- все цифры — только из выполненного кода.

**Особенности окружения:**
- у пользователя Windows без Docker;
- российский аккаунт на bybit.com;
- статический российский IP.
- API Bybit закрыт из облачной среды (CloudFront 403). Поэтому данные качает
  пользователь `.bat`-файлами, загружает zip в GitHub Releases (`data-v1` — HYPE
  по минутам, `data-v2` — корзина 15m), а исследование скачивает их оттуда.
- Комиссии пользователя (Non-VIP): мейкер 0,02 %, тейкер 0,055 %.

## 3. Результаты исследования (все цифры — из `reports/`)

1. **Только HYPEUSDT, 15m–4h** (`STAGE3_RESEARCH.md`): ничего не прошло.
   - У частых конфигураций нет перевеса даже без учёта издержек.
   - Пробои на 15m хуже случайных входов.
   - «Почти кандидат» — импульс 1h/4h: PF 1,24 / 1,16, но всего ~30 сделок за полгода.
2. **Корзина из 15 монет, протокол записан заранее** (`STAGE3B_BASKET.md`, `BASKET_PROTOCOL.md`),
   риск 5 %, 4h и 1d: финалиста нет.
   - При 5 % и до 4 связанных позиций просадки 75–80 %, бот останавливается.
   - Пример: 10 USDT → 75 → 15.
3. **Диагностика всей сетки без подбора** (`basket_diag.txt`):
   - трендовые стратегии на 4h: +0,08…+0,24 R на сделку, в плюсе 90–98 % вариантов;
   - межмонетный импульс, «против перегретых» по финансированию, «против толпы»: перевеса нет.
4. **Разведка после протокола** (`basket_explore*.txt`): пробой канала 4h при риске 1–2 %.
   - PF 1,30–1,37, ~700 сделок за 27 месяцев.
   - Кандидат выбран задним числом; с поправкой на 36 попыток статистически не доказан
     (дефлированный Шарп 0,46–0,50).
5. **Одна проверка на отложенных данных** 2026-04 — 2026-10 (`STAGE3C_HOLDOUT.md`):
   пробой 4h, 25 USDT, риск 2 %. **Не пройдена.**

   | | Бот | Buy & hold корзины |
   |---|---|---|
   | 25 USDT → | 44,95 (+80 %) | 46,65 (+87 %) |
   | Профит-фактор | 1,35 | — |
   | Сделок | 182 | — |
   | Макс. просадка | 65 % | 25 % |
   | Шарп | 1,53 | 2,36 |

   - Почти вся прибыль — 2 сделки; без них остальные 180 сделок дали −6,64 USDT.
   - Входы лучше случайных только в 64 % случаев.
6. **1h и 15m, риск 2 % и 5 %** (`basket_lowtf.txt`; данные уже не чистые): все варианты
   доходят до остановки на −80 %.
   - Издержки съедают 0,04–0,09 R на сделку, до издержек перевеса почти нет.
   - Дожил и вырос только пробой 4h при 2 %: 25 → 185 USDT за 2024–2026, просадка 65 %.
     Это оптимистично: две трети периода — данные, на которых он выбирался.

## 4. Что сделано правильно

- **Честная методология:**
  - правила проверки записывались до запуска;
  - walk-forward с подбором только на прошлом;
  - отложенные данные открыты один раз, это видно в журнале `reports/holdout_access.log`;
  - поправка на число попыток.
- **Реализм бэктеста:**
  - комиссии, проскальзывание, исполнение стопа хуже цены;
  - финансирование, ликвидация в изолированной марже;
  - минимальный ордер и шаги объёма;
  - все ограничители риска.
- **Защита от ошибок в коде:**
  - тесты подмены будущего ловят намеренно встроенные «подглядывания»;
  - два движка сверены между собой;
  - сделки пересчитаны независимым скриптом.
- **Риск-модуль готов для боевого режима:** объём от риска, плечо, ограничители с
  сохранением состояния.

## 5. Что не так или под вопросом

**Ограничения данных:**
- **Смещение выживших.** Корзина отобрана по сегодняшнему обороту, исчезнувших монет
  нет. Лонги и buy & hold на истории завышены.
- **Для корзины нет mark-цен.** Ликвидация считается по последней цене.
- **Путь внутри свечи — 15m.** При стопе и тейке в одной свече считается, что первым
  сработал стоп.
- **Исполнение.** Вход по открытию следующей 15m-свечи с проскальзыванием 0,02 %. На
  пампах неликвидных монет (MOVR) реальное исполнение может быть хуже.

**Статистика:**
- Много попыток (≥ 36 прогонов walk-forward плюс справочные раунды), кандидат найден
  задним числом.
- Подбор параметров шумный: сдвиг границ квартала на 1 день поменял выбранный трейлинг
  и PF квартала с 1,24 на 0,68 (`basket_holdout_dryrun.txt`).
- Прибыль трендовой стратегии держится на редких больших сделках, и выборка этих
  сделок мала.

**Устройство риска:**
- Корреляция монет при расчёте объёма не учитывается.
- Лимиты «4 позиции, 20 % суммарного риска» выбраны вручную.
- Нет управления риском на уровне портфеля, например подстройки под волатильность.
  Именно это и есть главная причина просадок 65–80 %.

**Критерии приёмки:**
- Сравнение с buy & hold за 6 месяцев сильно зависит от рынка: за 2024 — март 2026
  корзина дала −32 %, за отложенные полгода — +87 %. Стратегия, которая торгует и в
  шорт, в сильный бычий рынок почти всегда проиграет покупке.
- Требование ≥ 100 сделок за полгода толкает к низким таймфреймам, где издержки
  съедают перевес.

**Чего не проверяли** (с 25 USDT и домашним ПК это в основном недоступно):
- стакан и микроструктура;
- маркет-мейкинг;
- арбитраж между биржами;
- ончейн-данные;
- машинное обучение;
- новости.

**Состояние проекта:**
- Отложенные данные израсходованы. Любую новую идею теперь можно честно проверить
  только на новых данных — торговлей на демо-счёте.
- Боевого движка нет: бот пока не умеет торговать.

## 6. Рекомендации для следующего шага

1. **Ожидания.** Бота с гарантированной прибылью не бывает. Сеточные боты и DCA (по
   сути мартингейл) не создают перевес, а перераспределяют риск: много мелких плюсов,
   затем крупный минус.
2. **Если строить бота сейчас:**
   - единственный кандидат с хоть какими-то доказательствами — пробой канала 4h на
     корзине (`bot/strategy/basket.py::Breakout`), риск 2 %, депозит 25 USDT,
     пересмотр настроек раз в квартал (`research/basket_wf.py`);
   - не ниже 4h и не выше 2–3 % риска: всё агрессивнее на истории доходило до −80 %.
3. **Порядок:** боевой движок (этап 4) → демо-счёт 1–3 месяца как проверка на новых
   данных с теми же критериями → реальные 25 USDT только при прохождении.
4. **Что стоит улучшить в исследовании:**
   - риск на уровне портфеля: учёт корреляции, подстройка под волатильность;
   - фильтр бокового рынка (из-за него убытки май—август 2026);
   - вариант только в лонг при бычьем режиме;
   - отдельная обработка неликвидных монет;
   - корзина без смещения выживших, с монетами, которые были в торговле на каждую
     дату в прошлом.
5. **Как продолжить в коде:**
   - сначала `hype-bot/docs/STATUS.md`;
   - тесты: `cd hype-bot && python -m pytest`;
   - данные: релизы `data-v1` и `data-v2` (команды в `STATUS.md`).
